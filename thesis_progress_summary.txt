二、Large 模块的详细说明

1. 模块定位
- Large 是在 DeepLabV3+ 基础上提出的上下文增强模块
- 它不改 backbone，仍然使用 ResNet101
- 它也不替换 DeepLabV3+ 的整体框架，而是替换原本单一的 ASPP neck 为 Hybrid Context Neck 的 large 版本

2. 整体结构
- 输入：backbone 的高层特征(high-level feature)
- 主分支：ASPP，负责标准多尺度空洞卷积上下文建模
- 增强分支：LargeKernelContextBranch，负责补充更大局部感受野
- 融合方式：不是直接拼接，而是残差增强

3. LargeKernelContextBranch 的实现思路
- 先用 1x1 卷积把输入特征压到 residual_channels（当前默认 128）
- 然后做大核深度可分离卷积（当前 large 版本默认 kernel_size = 9）
- 再把原始压缩特征和大核分支输出拼接
- 最后再经过 1x1 投影和 Dropout 输出到与 ASPP 相同的通道数

4. Large 模块的门控与残差
- 大核分支输出后先经过 ChannelGate
- ChannelGate 用全局平均池化 + 两层 1x1 卷积学习每个通道的重要性
- 模块内部还有一个可学习的缩放参数 large_scale_logit
- 实际融合方式是：
  enhanced = aspp_feat + sigmoid(scale) * gated_large_feat
- 这样做的好处是：
  1）一开始不会过度破坏 ASPP 基线
  2）模型可以自己学会 large 分支到底要注入多少信息
  3）整体训练更稳

5. 为什么 large 有效
- ASPP 已经有多尺度上下文，但对某些连续结构类的局部大范围建模仍不够
- large 分支通过更大的卷积核补充区域连续性和局部上下文
- 从实验看，large 相比 baseline 的提升主要说明：
  1）结构改进确实有效
  2）不需要引入过多复杂分支，也能在整体 mIoU 上取得稳定提升

6. 为什么最终不用 V3 / strip / learnable+aux 作为主模型
- V3 更复杂，但没有超过 large
- strip 分支容易带来误增强，不够稳定
- learnable+aux 更偏边界优化，虽然 BF1 变好，但整体 mIoU 没有超过 large
- 因此最终教师模型应定为：Hybrid Large


三、当前阶段的总体结论

1. 教师模型主线已经明确
- 最终教师：Teacher_Baseline_large
- 结论：Hybrid Large 是当前最优结构

2. 复杂结构和训练技巧的作用已经基本清楚
- largeV3：更复杂，但不如 large 稳
- learnable+aux：提升 BF1，但不提升整体 mIoU
- OHEM：提升 BF1，但未提升整体 mIoU

3. 预处理结论已经初步明确
- 无预处理最差
- 基线预处理在本域 Cityscapes 上最优
- 充分预处理虽然没有取得最高 mIoU，但边界指标更强，可能更有利于跨数据集泛化

4. 学生模型结论
- Student_Baseline 达到 0.685389，属于正常、可接受的 baseline
- 教师与学生仍有显著差距，因此蒸馏仍值得做
